# 用已有小器件扩展宠物应用

先完成核心应用，再一次添加一种外设。每个扩展都接到“输入事件 → 应用状态机 → 输出动作”结构中，避免把 GPIO、驱动调用和菜单逻辑混在一起。

下列是扩展课程规格，尚未编写对应驱动。雷达、风扇、扬声器、电机和驱动模块的具体型号未确认，不能仅凭器件名称确定接线与代码。旋转编码器已经进入主线。

| 顺序 | 你的器件 | 小用例 | 集成到宠物 | 先确认 |
| --- | --- | --- | --- | --- |
| X1 | 无源小音响 | 播放单音、短提示音、非阻塞旋律 | 喂食/选择音效 | 压电蜂鸣器还是动圈扬声器；阻抗、额定功率、是否有功放 |
| X2 | 人体雷达 | 串口打印无人/有人，延时消失过滤 | 有人靠近时宠物打招呼 | 雷达型号、UART 或数字输出、供电与输出电平 |
| X3 | 舵机 | 限定安全行程内定点、平滑移动 | 开心时摆尾 | 舵机类型、电源、脉宽范围、机械限位 |
| X4 | 直流散热风扇 | 开关，再按支持方式调速 | 制作环境页或通风演示 | 2/3/4 线、电压电流、PWM 和转速接口定义 |
| X5 | 步进电机 | 单步、方向、计数，再加减速 | 机械展示台随宠物状态转动 | 电机型号、额定电流、驱动器、是否有原点开关 |

**这些功率负载不能由 ESP32 GPIO 直接供电。** 普通低阻动圈扬声器需要功放；风扇和电机需要合适驱动与供电；舵机电源按实际电流需求设计，控制信号与电源正确共地。确认型号后再选驱动，不把压电蜂鸣器的接法套到普通喇叭，也不把两线风扇的开关方法套到四线 PWM 风扇。

## X1：提示音

如果是合适的压电蜂鸣器，学习 LEDC 频率与占空比，再编写音符序列调度器。如果是动圈扬声器，先确定功放接口，可能学习 I2S 音频输出。

验收：菜单输入期间音符能准时结束；取消音效立即静音；播放过程不阻塞界面。独立练习：将音符频率/时长放入常量数组，新增旋律不修改播放器逻辑。

## X2：雷达

先确认协议。数字输出型先学习边沿和稳定判定；UART 型先学习接收缓冲、帧头、长度、校验和半包处理。雷达“有人”不能直接当作“识别了某个具体人”。

验收：静止存在和运动事件按照模块能力正确区分；串口断帧或噪声不会误改游戏状态；连续无人达到指定时间后才切换待机。独立练习：增加事件冷却时间，防止频繁打招呼。

## X3：舵机

先固定电机并去除会碰撞的机构。确认脉宽与行程后，用 LEDC/MCPWM 输出控制信号，再按小步长改变目标位置。普通位置舵机与连续旋转舵机的信号意义不同。

验收：目标超范围被限制；切换菜单不停止控制周期；堵转或电源不足不会通过软件无限重试。独立练习：把动作定义成时间/位置关键帧，控制任务只执行轨迹。

## X4：风扇

先验证合适驱动下的开关，再根据风扇接口决定调速。四线风扇的 PWM 输入电气方式、频率和最低转速不能照搬一般 GPIO PWM。

验收：启动可靠，低速规则明确；有转速输出时用 GPIO/PCNT 计数，并根据每圈脉冲数换算 RPM。独立练习：在屏幕上显示转速曲线，只刷新曲线区域。

## X5：步进电机

先学习驱动器使能、方向与步进脉冲，再学习速度变化与原点。ULN2003 相序驱动与 STEP/DIR 驱动器是不同接口，不能混用教程。

验收：启停有受控加减速，方向正确；复位后在没有原点传感器的情况下不声称知道绝对位置。独立练习：将“回原点、空闲、运动、故障”写成明确状态机。

## 软件进阶

- PCNT 编码器：替换当前低速轮询，但仍输出相同 UP/DOWN 事件。
- 双缓冲：一块 DMA 发送时绘制另一块；记录两块缓冲的所有权与完成事件。
- LVGL：保持 Pet 和 Event 不变，仅替换显示/导航层；固定版本并理解 flush 完成时机。
- BLE 可靠命令：增加命令序号、执行结果与去重，避免把状态快照当成逐条 ACK。
- 中文字模与位图：先用 Python 工具生成有限字符或像素数组，核对行顺序、颜色和 Flash 占用。
- 移植到 C：当前原生 ESP-IDF 使用 C++，可把类改成结构体与函数，以比较两种模块组织方式。
