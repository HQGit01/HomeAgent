# 验证记录

本次使用本机已有原生 ESP-IDF 5.4（安装登记为 5.4.0）及 Xtensa GCC 14.2.0 编译。未使用 PlatformIO 或 Arduino，没有烧录、擦除或控制实际开发板。

## 已完成的构建验证

通过 `tools/verify_builds.py` 在原生 ESP-IDF 环境中完成三个构建，退出码均为 0：

| 构建选择 | 检查目的 | 应用镜像大小 | 结果 |
| --- | --- | --- | --- |
| COURSE_LESSON=0 | 基础入口、全部课程源文件编译 | 0x331c0 字节 | 编译、链接、镜像生成通过 |
| COURSE_LESSON=17 | 完整宠物、GPIO/队列、LCD、BLE、NVS 链接 | 0x89860 字节，约 550 KiB | 编译、链接、镜像生成通过 |
| COURSE_LESSON=99 | 模型边界自检固件 | 0x32840 字节 | 编译、链接、镜像生成通过 |

所有课程源文件都由 main 组件列出，因此构建会检查全部 18 课及自检源码。最终课单独链接验证了所用外设和蓝牙符号；没有逐一启动全部 18 课。

实际构建配置已核对：target=esp32，Flash=4 MB，NimBLE 启用，FreeRTOS tick=1000 Hz，断言启用，主任务栈=8192 字节。完整应用镜像占 3 MB 应用分区约 18%；这不是运行时 RAM 占用。

原始结果在 `build/validation/results.json`，日志分别为 `lesson0.log`、`lesson17.log`、`lesson99.log`。验证目录会被重复使用，最后留下的是 **99 课自检固件**，不要把它当成最终宠物固件烧录。请按实验指南在独立的 build/lesson17 目录构建并烧录最终课。

本机 ESP-IDF 自身的 Git 子模块版本查询输出过 `bad object HEAD` 元数据警告；未修改 SDK 安装目录。本次三个编译流程仍均以 0 返回并成功生成镜像，日志保留该信息供环境排查。

## 已提供但尚未执行的运行测试

`tests/model_cases.h` 对固件真实使用的模型调用断言，覆盖：

- 空菜单、首尾循环、滚动窗口；
- 按键抖动、短按、长按释放互斥、毫秒时间戳回绕；
- 编码器正反转、反向抖动抵消、非法相位跳变；
- 睡眠限制、精力不足、属性饱和、分段时间更新与长间隔；
- 存档往返、截断、空指针、单字节损坏、有效校验下的越界属性；
- BLE/输入命令的大小写与非法字符。

自检固件已经编译，但**没有在实际 ESP32 上运行这些断言**。没有找到可直接使用的主机 C++ 编译器，因此提供的 `tests/host_main.cpp` 也未在电脑上执行。不能将“测试源码编译通过”表述成“全部测试运行通过”。

## 仍需你的硬件验收

屏幕分辨率、偏移、RGB/BGR、反显、背光、电源和接线；编码器每卡点相位数、方向与高速漏步；BLE 手机读写/订阅/断线恢复；DMA 完成回调实际行为；存档重启恢复；输入响应时间与两小时稳定运行，均需按 [实验指南](START_HERE.md) 实测。

## 复现

在已激活的 ESP-IDF Terminal 中运行：

```text
python tools/verify_builds.py
```

此脚本只构建，不执行 flash、erase-flash 或 monitor，也不安装依赖。首次编译 SDK 较慢，后续复用构建缓存。
